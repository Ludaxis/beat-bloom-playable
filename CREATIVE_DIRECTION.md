# Beat Bloom Phase 1 production direction

Build four interactive ads for Unity Ads, AppLovin and Meta. This is a separate advertising implementation, explicitly requested after the September 7 review; it does not add a second level loader or UI system to the Unity game.

Reference: Beat Bloom 1.0.3, current Main → Home → Play flow; current contour source and local music charts. Archived August screenshots are not the art reference.

## The experience

The viewer chooses a front-row colour ball, watches its numbered power clear matching contour segments, and earns more of the real song. The board is physically simulated. Wrong colours bounce; occupied centre slots and the tray matter. No forced store navigation, scripted fake losses, beat-timing claim or purchased-power step.

Footer variants emphasise fluent musical satisfaction. Logo/tagline variants introduce a readable colour-order decision. Each concept has NO BATIDÃO/Heart and Sunflower/Flower. This compares concept bundles, with song and shape paired.

## Visual plan

- Midnight violet #151033: the current game's stage.
- Electric violet #9464ff: structure and secondary feedback.
- Pink #ff58a5, cyan #38d5ff, lime #9af04a: clear playable colour identities.
- Warm yellow #ffd34a: the existing game's prominent play/install action.
- Lilita One: the game's own display/ball-number font. System sans: supporting instructions and review controls.
- A portrait stage centres the current heart/flower geometry. A small instrument strip sits above it; capacity/tray and two queue fronts sit below; install occupies a separate labelled footer.
- The changing contour is the memorable element. Background echoes, particles and instrument responses support meaningful actions. The interface remains readable without sound.

Layout: small brand/song row → concise instruction → instrument progress → large segmented shape → capacity/tray → colour queue → explicit install. Landscape keeps the portrait puzzle beside the instruction and CTA rather than stretching the silhouette.

Review of the plan: neon and violet are grounded in the current game, not a generic web theme. Existing logo/icon and instrument art establish continuity. A long splash, oversized mascot and decorative dashboard chrome would obscure the first choice, so they are omitted from the playable opening.

## Acceptance

All four variants start, accept real choices, clear a solvable board and reach replay/install. Real local stems start only after a gesture, remain synchronized and pause when hidden. Exported gameplay is self-contained. No gameplay interaction exits the ad. Package sizes, adapter behavior, console errors, multiple viewports, replay and reduced-motion behavior are checked. Network upload/moderation, actual mobile WebView audio and paid-media rights remain release checks requiring the relevant external environments/owners.
